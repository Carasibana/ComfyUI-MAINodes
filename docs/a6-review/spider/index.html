A6 review: NVFP4 / FP8 activation arms beside their metrics

Scene: spider (2D anime, 90 f T2VA, 25 steps, 1376x768, shot cut at 3.0 s) (all scenes). Same-seed. Every arm fake-quantises the activations of a region of the shipped W4A8 model; weights stay int4 g16, so a real NVFP4 checkpoint would move further than any arm here. The reference is the exact W4A8 arm (ref_w4a8_exact). Latent mean |dx| counts dose, not damage (kvi8r "perfect" = 0.24; one NVFP4 block = 0.35; FP8 everywhere = 0.75 vs NVFP4 everywhere 0.78 at 3x lower per-op error), so the pixel / flow / audio rulers below are there to be calibrated against your eyes, not to judge. Click a clip to play it with sound; hover plays muted; d on a card swaps in the amplified |arm - ref| view. Star the candidates, send two to A/B, flip with f, wipe with the slider.
Rulers that separated the arms on first build: PSNR vs ref falls monotonically with latent |dx| (19.6 to 11.7 dB); motion-curve corr is bimodal, ~0.97 = the two big events (frame 32 and the shot cut at 71/72) land on the same frames, ~0.5 = one event slid a frame (worst-frame PSNR 7-8 dB), below 0.3 = events moved several frames; audio corr stays above 0.9 for most single-decade arms and drops to 0.77 for NVFP4 everywhere.
Cost columns: wall s is the measured time of THIS run, a fake-quant arm on the shipped W4A8 model, so it carries the quantiser's overhead (arms run 2-10% slower than the reference, FP8's quantiser slowest) - it is not the regime's speed. Δ weights and GEMM time are [PROJ]ections of what the regime would buy if built with real weights: bytes from the file headers: W4A8 218.8 MB/block vs real NVFP4 218.5 (both 4.54 bits/param, so the NVFP4 weight delta is ~0) vs FP8 ~1 B/param, GEMM ms from the 16k-row bench (qkv 5.4/3.7/6.5, out 2.9/1.9/2.4, fc1 10.5/6.2/9.9, fc2 5.6/3.9/5.0 ms W4A8/NVFP4/FP8), block GEMMs being ~15-20% of a step at 217k tokens and more at 29k. Segment arms route activations by token row, so their weight delta is 0 and their GEMM saving scales with the token share (~0.92 video). Measured VRAM per arm was not recorded (no poller rode along; a fake-quant arm's peak would not be the regime's anyway). All-NVFP4 weights save NOTHING over the shipped W4A8 file (12.53 vs 12.54 GB, measured 2026-08-19 on the real build): the NVFP4 prize is GEMM speed and the dropped int4-to-int8 decode, not bytes.
